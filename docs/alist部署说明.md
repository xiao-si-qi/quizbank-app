# alist 部署说明（已按此配置好你的实例）

这份文档记录 `https://alist.xiaosiqi.cn` 上已经做好的题库与权限配置，以及 App 该怎么填。
以后自己加题库、加学生，照这份文档改就行。

## 一、已经建好的结构

```
/题库/
├── 题库清单.xlsx              ← 你原有的文件，没动
├── 题库清单-全部.xlsx          ← 新：完整目录表（登录后可见，含内部题库）
├── 公开/                      ← 匿名可读
│   ├── 题库清单-公开.xlsx      ← App「免登录模式」用的目录表
│   ├── 计算机基础.xlsx         （12 题：单选/多选/判断/填空/简答）
│   ├── 生活常识.xlsx           （8 题）
│   └── images/http-flow.png   （题目里引用的图片，验证图片链路）
├── 内部/                      ← 需要登录才能看到
│   └── 消防安全-内部.xlsx      （10 题）
└── 成绩/                      ← 成绩目录，每人一个子目录
    ├── student1/  student2/  student3/  teacher/
```

「题库清单」里的**文件地址用的是 alist 绝对路径**（`/题库/公开/计算机基础.xlsx`）。
App 会自动按当前账号的根目录换算，所以同一份清单对管理员和普通用户都能用，换服务器也不用改表。

## 二、权限是怎么配的

这个 OpenList 构建**没有角色 API**，权限 = 每个用户的 `base_path` + `permission` 位掩码，
再叠加**按路径的 meta 授权**。meta 的关键字段（读源码 `server/common/check.go` 确认）：

| 字段 | 含义 |
|---|---|
| `read_users` / `write_users` | **用户 ID 列表**（不是用户名）。**非空即为白名单**：不在名单里的人会被拒绝 |
| `read_users_sub` / `write_users_sub` | 是否对子目录同样生效 |
| `write` / `w_sub` | **不是只读开关**！它是「绕过用户权限位、授予写入」的开关，别乱开 |
| 路径优先级 | 取**最近（最长前缀）**的那条 meta |

两个容易踩的坑：

1. **管理员也不豁免**。`CanRead`/`CanWrite` 里没有 admin 特判，
   所以每条白名单都要把管理员 ID（1=xiaosiqi、4=admin）写进去，否则你自己也会被挡住。
2. **alist 的路径相对于用户自己的 `base_path`**（源码就是 `path.Join(basePath, reqPath)`）。
   学生 `base_path=/题库`，那么请求 `/题库/内部/a.xlsx` 会被拼成 `/题库/题库/内部/a.xlsx`。
   App 已经处理了这个换算（会先减掉账号根目录再发请求）。

### 实际配置的 meta

| 路径 | 可读 | 可写 |
|---|---|---|
| `/题库` | 不限 | 仅 1, 4（管理员） |
| `/题库/内部` | 1, 4, 5, 6, 7, 8 | 仅 1, 4 |
| `/题库/成绩` | 1, 4, 8（teacher） | 仅 1, 4 |
| `/题库/成绩/student1` | 1, 4, 5, 8 | 1, 4, 5 |
| `/题库/成绩/student2` | 1, 4, 6, 8 | 1, 4, 6 |
| `/题库/成绩/student3` | 1, 4, 7, 8 | 1, 4, 7 |
| `/题库/成绩/teacher` | 1, 4, 8 | 1, 4, 8 |

`/题库` 这条是「总闸」：因为它 `write_users=[1,4]` 且对子目录生效，
所以**学生即使有写权限位，也无法改动题库树里的任何文件**；
只有到了 `/题库/成绩/<自己>` 这条更精确的 meta，写权限才被放行。

## 四、App 里怎么填

### 免登录（只看公开题库）

| 设置项 | 填什么 |
|---|---|
| 服务器地址 | `https://alist.xiaosiqi.cn` |
| 用户名 / 密码 | 留空 |
| 题库列表地址 | `/题库/公开/题库清单-公开.xlsx` |

### 学生（student1）

| 设置项 | 填什么 |
|---|---|
| 服务器地址 | `https://alist.xiaosiqi.cn` |
| 用户名 / 密码 | 你自己建的学生账号 |
| 题库列表地址 | `/题库/题库清单-全部.xlsx` |
| 成绩目录 | `/题库/成绩/student1` |
| 署名 | 例如 `张三`（默认用 alist 用户名） |

### 老师 / 管理员

| 设置项 | 填什么 |
|---|---|
| 用户名 / 密码 | `teacher`/`你的密码` 或 `xiaosiqi`/你的密码 |
| 题库列表地址 | `/题库/题库清单-全部.xlsx` |
| 成绩目录 | `/题库/成绩`（管理员会写到 `/题库/成绩/<署名>/`） |

用管理员登录后，成绩页的「全部用户」就能看到所有人的成绩与逐题作答记录。

## 五、以后怎么加东西

**加一个公开题库**
1. 按 `docs/Excel格式规范.md` 做好 xlsx，传到 `/题库/公开/` 下（图片放 `/题库/公开/images/`）。
2. 打开 `/题库/公开/题库清单-公开.xlsx`，加一行：题库名称 + 文件地址（写 `/题库/公开/xxx.xlsx`）。
3. 想让登录用户也能看到，就把同一行加到 `/题库/题库清单-全部.xlsx`。

**加一个内部题库**
1. 文件传到 `/题库/内部/`。
2. 只在 `/题库/题库清单-全部.xlsx` 里加一行。

**加一个学生**
1. alist 后台 → 用户 → 新建：用户名、密码、根目录填 `/题库`、权限勾上「上传」（其它不勾）。
2. 在 `/题库/成绩/` 下建同名目录。
3. 到元信息（meta）里照着 student1 的样子加两条：
   - `/题库/成绩/<新用户名>`：可读 `<新用户ID>,1,4`，可写 `<新用户ID>,1,4`
   - 把这个新用户 ID 追加到 `/题库/成绩/student*/` 各条的「可读」里（让老师能看到他的成绩）

> 用户 ID 在 alist 后台的用户列表里，或者用 `GET /api/admin/user/list` 查。

## 六、顺手发现的两件事

1. **`/115网盘` 的登录态已失效**：返回「该账号于 12:45 在 115生活_安卓电视端 主动退出」。
   如果还在用这个存储，需要重新登录一次。
2. **`admin` 这个账号（id=4）根目录是 `/`**，也就是说它能读到整个网盘的内容
   （包括所有人的成绩）。如果不是有意为之，建议把它的根目录收窄到需要的范围。

## 七、联调测试怎么跑

App 的 alist 层带了一个**真实服务器联调测试**（默认跳过，不传参数就不跑）：

```bash
./gradlew :core:test --tests "*AlistLiveIntegrationTest*" \
  -Dalist.baseUrl=https://alist.xiaosiqi.cn \
  -Dalist.student=student1 -Dalist.studentPwd=（你自己设的密码）
```

它会用 App 真正的代码去验证：匿名只能读公开题库、学生能读内部题库、
学生只能写自己的成绩、**改写题库会被拒绝**、图片能下载并校验格式。

> 这套联调测试在第一次跑的时候抓出了两个致命 bug：
> 一是 alist 路径相对 `base_path`（会让所有非管理员账号都找不到文件），
> 二是 `fs/get` 的 `header` 字段实际是空字符串而不是对象（会让**每一次文件下载**都解析失败）。
> 两个都已修复并补了回归测试。

## 当前实例的题库布局（xiaosiqi.cn）

已经配好并验证过的一套目录结构，可以直接照着用：

```
/题库
├── 公开/
│   ├── 题库清单-公开.xlsx      ← 匿名可见的目录（App 默认读这个）
│   ├── 计算机基础.xlsx  （12 题）
│   ├── 生活常识.xlsx    （8 题）
│   └── images/                ← 题目里引用的图片
├── 内部/
│   ├── 消防安全-内部.xlsx      （10 题）
│   ├── 信号工-2017车站与区间高级工题库.csv  （1393 题）
│   ├── 信号工-2016高级工复习题.csv          （1433 题）
│   └── 信号工-高级工题库-第三部分.csv        （513 题）
├── 题库清单-全部.xlsx          ← 登录后才读得到的目录（含上面全部）
└── 成绩/
    ├── student1/  student2/  student3/  teacher/
```

权限（用 alist 的「元信息」功能配）：

| 路径 | read_users | write_users | 效果 |
|---|---|---|---|
| `/题库` | 空（人人可读） | 1,4 | 只有管理员能改题库 |
| `/题库/公开` | 空 | — | 匿名可读 |
| `/题库/内部` | 1,4,5,6,7,8 | — | **必须登录**才能读 |
| `/题库/成绩` | 1,4,8 | — | 管理员/老师能看所有人成绩 |
| `/题库/成绩/<用户名>` | 该用户 + 1,4,8 | 该用户 | 只能写自己的成绩目录 |

> `read_users` / `write_users` 填的是**用户 ID**（不是用户名）；留空表示不限制。
> 权限是「就近继承」的：子目录没配就用最近一层配过的规则。

已用真实账号验证过：匿名读不到 `/题库/内部`，登录用户能读；
学生只能写自己的成绩目录，改不了题库。
